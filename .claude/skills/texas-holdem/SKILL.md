# 德州撲克（Texas Hold'em）規則與實作限制

這份文件是實作德州撲克遊戲的規則依據。**這個功能是用真正的 Java Paper 外掛實作的（專案在 `C:\Users\tt\Desktop\plugin`，package `com.tank1114.holdem`），不是用 Skript 腳本**——修改程式碼前先確認邏輯符合這裡的規則；「客製化限制」章節記錄的是這個伺服器版本要跟真實規則不一樣的地方，以那裡為準、覆蓋掉標準規則。

## 基本設定

- 使用一副 52 張牌（無鬼牌），每位玩家發 2 張「底牌」（hole cards），牌桌上會出 5 張「公共牌」（community cards）。
- 玩家人數：2～10 人一桌。
- 桌上有一顆「莊家鈕」（dealer button），每局結束後順時針移動一位。

## 位置與盲注

- **小盲注（Small Blind, SB）**：莊家鈕左手邊第一位，開局前強制下注。
- **大盲注（Big Blind, BB）**：小盲注左手邊，開局前強制下注，金額通常是小盲注的 2 倍。
- 只有兩人對戰（Heads-up）時例外：莊家鈕同時是小盲注，對家是大盲注。

## 遊戲流程（一局的四個下注輪）

1. **翻牌前（Pre-flop）**：每人發 2 張底牌後，從大盲注左手邊的玩家開始下注。
2. **翻牌（Flop）**：開出 3 張公共牌，從莊家鈕左手邊第一位還在場上的玩家開始下注。
3. **轉牌（Turn）**：再開 1 張公共牌（總共 4 張），下注順序同上。
4. **河牌（River）**：再開 1 張公共牌（總共 5 張），下注順序同上，也是最後一輪下注。
5. **攤牌（Showdown）**：河牌下注輪結束後，留在場上的玩家亮出底牌，用「底牌 2 張 + 公共牌 5 張」湊出最大的 5 張牌組合，牌型最大者贏得底池（Pot）。

每一輪下注中，只要所有還沒棄牌的玩家的下注金額都相等（或全部 all-in），這一輪就結束，進入下一階段。

## 下注動作

玩家輪到自己時，可以做以下動作之一：

- **棄牌（Fold）**：退出這一局，放棄已下注的籌碼。
- **看牌（Check）**：本輪還沒有人加注時，不下注、直接輪到下一位。
- **跟注（Call）**：把自己的下注補到跟目前最高下注一樣。
- **加注（Bet / Raise）**：沒人下注時稱 Bet，已經有人下注後再往上加稱 Raise。
- **全下（All-in）**：把手上所有籌碼都投入。

加注規則（無限注 No-Limit，除非客製化限制另有規定）：
- 最小加注金額 = 本輪目前的下注金額 + 上一次加注的差額（至少要跟上一次加注的漲幅一樣多）。
- 玩家可以加注到自己所有籌碼（all-in），沒有上限。

## 邊池（Side Pot）

當有玩家 all-in 且籌碼比其他人少時：
- 主池（Main Pot）只計入到該玩家 all-in 金額為止、所有玩家都出的部分。
- 超過該金額、其他人繼續下注的部分另外算「邊池」。
- 攤牌時，all-in 的玩家只能爭主池；邊池由還有籌碼、繼續下注的玩家爭。
- 可能同時存在多個邊池（多人在不同金額 all-in 時）。

## 牌型大小（由大到小）

1. **皇家同花順（Royal Flush）**：同花色的 10-J-Q-K-A。
2. **同花順（Straight Flush）**：同花色的連續 5 張。
3. **四條（Four of a Kind）**：4 張同點數。
4. **葫蘆（Full House）**：3 張同點數 + 一對。
5. **同花（Flush）**：同花色 5 張，點數不連續。
6. **順子（Straight）**：連續 5 張，花色不同。A 可當最小（A-2-3-4-5）或最大（10-J-Q-K-A）。
7. **三條（Three of a Kind）**：3 張同點數。
8. **兩對（Two Pair）**：兩組對子。
9. **一對（One Pair）**：一組對子。
10. **高牌（High Card）**：以上皆非，比最大的單張。

牌型相同時比「踢腳牌」（kicker，剩餘單張由大到小依序比較）；若完全相同則平分底池（split pot）。

## 一局結束

- 攤牌後或只剩一人未棄牌時，該局結束，贏家取得底池籌碼。
- 莊家鈕移到下一位，開始下一局（重新洗牌、發新的底牌與公共牌）。

## 客製化限制（這個伺服器版本的規定）

> 這裡記錄跟上面標準規則不一樣、或標準規則沒規定、需要額外定義的地方。目前尚未填寫，之後由使用者補充，補上後直接以此區塊為準。

### 實體牌桌與私人手牌

- 遊戲要有一個實際存在於 Minecraft 世界裡的牌桌場景，不是純聊天室文字介面。
- 公共牌（河牌，即 Flop/Turn/River 開出的牌）要顯示在桌面上，**所有在場玩家都看得到**。
- 每位玩家自己的 2 張底牌要顯示在自己的座位上，**只有本人看得到，其他玩家（包含其他座位的玩家、旁觀者）都看不到**。

**技術做法**：
- 桌面上的牌用 Item Display 顯示實體呈現（每個座位固定一組底牌顯示位置 + 桌面中央一組公共牌顯示位置）。
- 公共牌的 Item Display 正常生成，所有人可見，不做隱藏處理。
- 每位玩家座位的底牌 Item Display 生成後，用 Paper API 原生的 `Player#hideEntity(Plugin, Entity)` / `showEntity(Plugin, Entity)`，把該實體對除了該座位玩家以外的所有人隱藏（這個可見性設定不會跨玩家重新登入、傳送、區塊重新載入持續存在，這些事件要重新套用一次隱藏設定）。
- 不需要額外外掛依賴（例如 SkBee）——這是原生 Paper API 就能做到的事，外掛本身零額外依賴。

**已決定**：
- 牌面素材：**不做自訂資源包**，用純原版物品呈現，靠命名（顯示名稱）標出花色與點數，例如把 Item Display 顯示的物品命名成「♠A」「♥K」這種文字，玩家不需要額外下載任何東西就看得到。物品本身種類（例如統一用紙張 Paper）只是牌面文字的載體，不用另外做外觀分辨。
- 牌桌部署：**先做固定一張牌桌，6 人座**，在伺服器世界裡指定一組固定座標蓋一張桌子、固定座位點（含每個座位的底牌 Item Display 位置、桌面中央的公共牌 Item Display 位置）。座標由管理員在遊戲內用 `/holdemadmin setup center` 與 `/holdemadmin setup seat <1~6>` 站在對應位置設定，存進 `table.yml`。多桌/玩家自建桌子是之後才考慮的擴充功能，目前不必設計。

### 沒有真人莊家，系統自動發牌

- 這個遊戲**不需要任何玩家擔任「莊家」去手動發牌**。標準規則裡的「莊家鈕」只是決定下注順序/盲注位置的標記，每局結束自動移動到下一位，跟由誰發牌無關。
- 實際運作：每一輪下注只要**所有還沒棄牌的玩家下注金額都相等（或已全下）**，系統就自動結束這一輪、自動開下一張公共牌，不需要任何玩家手動觸發「開牌」。
- 換句話說，牌桌上不會有「莊家」這個角色/座位，所有座位都是普通玩家座位。

### 玩家怎麼上/下桌

- 玩家**右鍵點擊座位**（座位用實體/方塊標示，例如告示牌或特定方塊）即可入座；同一個動作也用來離座（例如再次右鍵，或右鍵一個明確的「離開」互動點）。
- 需要額外設計：座位要對應到固定牌桌的哪幾個實體/方塊、右鍵互動的判定範圍、以及座位「已被別人坐走」時要擋下並提示。

### 籌碼系統

- 使用**獨立虛擬籌碼**，只在這張撲克桌內流通，**不跟伺服器任何經濟外掛（Vault 等）或真實貨幣掛鉤**。
- 外掛自己用 `chips.yml`（UUID -> 籌碼餘額）持久化每位玩家的籌碼，重開伺服器籌碼會保留。
- **已決定**：起始籌碼 10000；籌碼歸零後的 re-buy 規則可由管理員即時切換（`/holdemadmin rebuy <AUTO|DISABLED|ADMIN_ONLY>`）：AUTO 自動免費補回起始籌碼、DISABLED 不能再要只能離座、ADMIN_ONLY 需要管理員用 `/holdemadmin chips give` 手動補。

### 斷線或逾時不下注

- 玩家**斷線，或輪到他超過時限仍未行動**，一律視為**自動棄牌（Fold）**，不影響其他人繼續進行這一局。
- **已決定**：逾時秒數為 60 秒（`config.yml` 的 `turn.timeout-seconds`），目前沒有倒數提示。

### 邊池餘數分配

- 平手分池時如果籌碼除不盡，多出來的 1 顆籌碼照撲克慣例，分給**莊家鈕左手邊最近（最早行動）的那位贏家**。

### 系統自動處理、不需要另外決定的技術細節（實作時要注意）

- 底牌的隱藏效果（SkBee Show/Hide）不會在玩家重新登入、傳送、區塊重新載入後自動保留，實作時要在這些事件重新套用一次隱藏設定，避免短暫穿幫。
- 對所有下注動作要做合法性檢查（不是輪到自己的人不能動作、下注金額不足最小加注、籌碼不夠還想跟注等），檢查失敗要有清楚的提示訊息、不能讓遊戲狀態卡住。
- 要提供一個**管理員救援指令**（例如 `/holdem reset`），在某一局卡住或出現異常時可以強制結束/重置這張牌桌，不然只能重啟整台伺服器。
